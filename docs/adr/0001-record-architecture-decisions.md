# ADR 0001: Registrar decisiones de arquitectura

**Estado:** Aceptado  
**Fecha:** 2026-07-09

## Contexto

PRISLAB SaaS ha crecido de forma rápida con múltiples editores, módulos y bloques enterprise. Necesitamos un registro claro de decisiones arquitectónicas importantes para evitar que el conocimiento se pierda o se repitan debates.

## Decisión

Usaremos Architecture Decision Records (ADRs) en `docs/adr/`, siguiendo el formato de Michael Nygard.

## Consecuencias

- Cada decisión importante queda documentada con contexto, decisión y consecuencias.
- Los nuevos colaboradores pueden entender por qué se eligió cada enfoque.
- Añade overhead de documentación, pero reduce riesgo de decisiones inconsistentes.
